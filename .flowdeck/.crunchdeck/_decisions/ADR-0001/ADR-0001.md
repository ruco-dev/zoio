# ADR-0001: Initial Technology Stack

**Date:** 2026-09-08
**Author:** TBD — repository maintainer
**Status:** Accepted

---

## Context

> Zoio needs an installable, local-first CLI that can orchestrate AI visibility scans, keep credentials local, persist portable JSONL evidence, and remain easy to test offline.

## Decision

**We will build Zoio as a Node.js 20+ TypeScript npm CLI with testable core modules, local JSONL persistence, and fixture, Codex CLI, and optional direct OpenAI search adapters.**

## Rationale

### Pros

- TypeScript and Node.js provide a fast, familiar distribution path through npm and a single executable entry point.
- The adapter boundary permits deterministic fixture testing while keeping live credential handling local.
- JSONL makes runs inspectable, portable, append-friendly, and free of backend infrastructure.

### Cons

- Live scans depend on locally available Codex or OpenAI credentials.
- JSONL is not a replacement for a multi-user query service or analytics database.

## Alternatives Considered

### Option A: Hosted web application and backend

**Description:** Build a dashboard backed by a remote API and database.

**Pros:** Centralized analytics and easier shared access.

**Cons:** Requires accounts, operations, remote data handling, and additional cost.

**Why rejected:** It conflicts with the MVP's explicit local-first, private-by-default constraints.

### Option B: Direct OpenAI API only

**Description:** Require an API key and call OpenAI directly for all scans.

**Pros:** One provider integration and direct API control.

**Cons:** Excludes authenticated Codex CLI users and makes the pocket default less accessible.

**Why rejected:** Supporting a Codex CLI adapter preserves a credential-local default while retaining direct API mode as an option.

## Consequences

### Positive

- Users can install and run Zoio locally without an account or backend.

### Negative

- Local result directories and provider credentials remain the user's responsibility.

### Risks

- Provider command and response formats can change; adapters and fixture tests must continue to isolate this variability.

## Implementation Notes

Keep argument parsing and terminal formatting in the CLI boundary. Store query, response, entity, citation, and run records under `zoio-results/` and preserve raw provider evidence.
